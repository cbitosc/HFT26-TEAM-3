# IMPLEMENTATION_ROADMAP

Version 3. **Implementation starts only after the architecture review gate is approved.** Each phase ends with:
- tests run;
- the API checked;
- the frontend checked (from phase 12);
- logs reviewed;
- regressions fixed;
- documentation updated.

A feature is not called done until it works on real or labelled synthetic data.

| 3 Video preprocessing | **Done (2026-10-30).** Every valid video gets a `preprocess` job after validation: a full frame index from container PTS (every frame, `time_ms` relative to the first frame, start offset kept as `pts_start_ms`); thumbnails, blur and brightness at 5 fps (configurable, never sampling inside gaps or past the last frame); a browser-safe H.264 playback copy that starts at 0 and is verified frame-for-frame against the original timing; frame-accurate full-resolution stills on demand; interval reprocessing at full rate; idempotent reruns. Live: a 20 s 1280×720 30 fps HEVC clip was processed (600 frames indexed, 100 sampled, transcoded) in 2.2 s on the M5, and the copy played and seeked exactly in a Chromium browser |
| 4 Object + accident detection | **Done (2026-10-30).** `detect` stage chained after preprocessing: YOLO26s (COCO → car, truck, bus, motorcycle, bicycle, pedestrian, traffic light) and the accident-cue model on sampled frames, one model run per model, idempotent reruns, optional accident cue (missing weights make the job partial, never block the detector). Weights load only through `models.lock.json`: pinned SHA-256 plus a static pickle scan against an allowlist (a crafted malicious checkpoint is refused without executing). `GET /evidence/{id}/detections` and `/model-runs`. Accident-model regression: our inference path reproduces Ultralytics' validator on the model's own validation split (mAP50 0.562 vs 0.558, tolerance 0.01). This check found and fixed a bug in our AP code (missing end-of-curve sentinel inflated AP; now equals Ultralytics' `compute_ap` on 200 random curves). 79 tests pass; mutation checks confirmed. Live: 20 s of 30 fps video → validate + preprocess + detect in 6.3 s (detector 21.8 ms/frame, accident cue 11.8 ms/frame, MPS). **Not yet measured:** detector accuracy on real dashcam data (BDD100K subset needs your go-ahead to download) |
| 5 Tracking | **Done (2026-10-30).** `track` stage chained after detection, running on stored detections (detector-independent): ByteTrack for CCTV, BoT-SORT with camera-motion compensation for dashcam (`roboflow/trackers`, Apache-2.0). Measured library behaviour: both trackers withhold each new object's first detection, which would start every track one sampled frame (200 ms) late. A deterministic, unambiguous-only backfill restores it, and is marked. Post-processing records gaps (never filled in), short tracks, possible identity switches, overlaps, border exits, and continuation candidates that are never merged. Metrics come from `trackers.eval` (TrackEval port: IDF1, ID switches, MOTA, HOTA) through a thin adapter. API: `/evidence/{id}/tracks`, `/tracks/{id}`, `/evidence/{id}/overlays`. 93 tests pass; mutation checks confirmed. Live: 20 s of 30 fps video → all four stages in 7.3 s; the bus and two pedestrians each kept one stable track across all 100 sampled frames; 18 of 377 detections stayed untracked (12 below the 0.3 track-start confidence, 6 one-off pedestrian boxes) and remain visible as untracked. **Not measured:** tracking accuracy on real labelled footage (BDD100K MOT), blocked like the detection subset |
| 6 Witness claims | **Done and verified live (2026-10-31).** Policy-gated Featherless client (cases must allow external inference), temperature 0, retries with backoff on 429/5xx (not 4xx), ledger of every call (hashes, attempts, tokens, latency; never the key), cache that never replays a failed answer. Claims need a strict schema (forbidden fields rejected) and every quote must be found verbatim in the original statement by code; unlocatable quotes are rejected, not fixed. One repair attempt, then the manual path (server cuts the quote from the stored text). Approximate times stay un-placed. Maneuver (left/right/straight) is also derived by code from the witness's own words, and the model's direction field is cross-checked against it. **Live findings:** the key works; the Qwen3-14B default produced empty or corrupt JSON on 6 of 10 statements because it spends its token budget on hidden reasoning; with `enable_thinking: false` it was valid on 10/10 and then 28/30 in a stability run (95% first attempt over 40 calls, median ~3 s, ~180 output tokens), all quotes verbatim; Qwen2.5-7B (3/10), Qwen2.5-32B (8/10, paraphrased quotes) and Qwen2.5-14B (10/10 valid but 3 paraphrased quotes) were worse; `response_format: json_object` returned an empty `{}` and is not used. The model's normalized fields are imperfect (e.g. a time phrase filed under `location`), hence the code-derived cross-check. Prompt-injection statement: the injected instruction was ignored. 123 tests pass; mutation checks confirmed. **Still unmeasured:** claim accuracy on real witness language at scale (10 synthetic statements only) |
