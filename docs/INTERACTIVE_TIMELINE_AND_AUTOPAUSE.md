# Interactive incident sequence, automatic pause and keyframes

Branch `claude/executive-overview`. Frontend work; `backend/` was not edited (it is Cursor-owned), so the backend items are listed as needs.

## How it works
- **One clock.** The video element owns time while playing; the store's `currentMs` (case ms) is the only timestamp state. The player, the timeline SVG, the sequence cards and the alert all read it.
- **Policy (`lib/alerts.js`).** Tier per validated event record: *possible accident* = `possible_collision` with an abrupt movement change, or a sensor `collision_flag`; *attention* = braking, slowing, stopping, direction change, near miss, a collision cue with no movement change (a weak cue); *information* = enters/leaves, steady maneuver. A raw detection or box overlap alone is never a trigger. Default: pause on possible accidents only; configurable in the UI (alert on attention events too; auto-pause on/off).
- **Trigger (`advance`, `useAutoPause`).** Cues within 3 s merge into one trigger led by the strongest (largest speed drop), so one incident pauses once. On continuous forward playback the first clock tick at or after the trigger raises the alert, pauses and seeks to the event's exact time. A backward seek of more than 100 ms forgets triggers after the new position (replay alerts again); a forward jump (scrubbing, clicking a card or keyframe) marks skipped triggers as seen without alerting; resuming never refires (the decoder landing a few ms early is ignored). Camera or scenario switches reset the state. With auto-pause off the alert is a notice and playback continues.
- **Exact seeking.** Events carry `start_ms` (case clock) and `observations.source_time_ms` (the video's own media time). Seeking uses the per-source shift from `/seek` (`media = case + shift`); a keyframe click uses the frame's media time minus that shift, and for a camera with no clock relation it makes that camera the clock instead of converting. Unsynchronized events have no case time, are never triggers, and are listed apart.
- **Keyframes.** From the existing `GET /storyboard`: before and after are the nearest stored samples on the same file outside the event, "event" is the nearest stored sample inside it, with its offset from the event labelled. A missing frame is not shown. Nothing is generated.
- **Alert.** Above the video (not over it): "Possible accident detected", "not a confirmed collision", camera, case and media time, event type, related tracks (identity not confirmed), supporting observations, uncertainty, keyframe strip, Resume, Open exact frame, View event details, Review evidence, and four investigator decisions. Dismissing records nothing.
- **Sequence.** The timeline panel now has time-ordered cards (time, plain sentence, tier, camera, thumbnail, evidence status, uncertainty, review status); the active card follows the playhead, expands to details and the keyframe strip; importance filter; camera filter is the existing one; Framer Motion fades with reduced-motion respected.

## Tests actually run
- `npx vitest run`: 170 passed, 0 failed (acceptance cases 1, 2, 8, 9, 10, 11, 13 and the alert/sequence UI are unit tests over the real trigger code).
- Real browser (`frontend/audit/e2e-accident-pause.mjs`, Chrome via playwright-core, live API, the real t-bone clip uploaded earlier): 11 passed, 0 failed: pause at the event (clock 4600 ms, within a frame), alert wording and camera, highlighted card, keyframe shown, resume without refiring, second event in order (5600 ms), manual rewind, replay alerts again, auto-pause off keeps playing, no console errors.
- `frontend/audit/e2e-no-alert.mjs` on two cases with no qualifying event: no alert (one case has 2 weak/attention events; neither paused).
- Not run: Firefox, Safari, touch, a three-camera synchronized case (no such case exists).

## Not done / needs the backend (see FRONTEND_V2_BACKEND_NEEDS.md)
Investigator decisions are saved in this browser only (no event-review endpoint, so no audit history); the policy is client-side (the backend does not label events with a tier); no new thumbnails or before/after extraction jobs (the stored sampled frames and thumbnails are used; an event between samples shows the nearest frame with its offset); variable-frame-rate precision depends on the backend's PTS index (the UI uses its media times as given); the main dashboard shows the executive summary, not a per-case incident sentence.
